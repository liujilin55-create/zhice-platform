# 网页计划书直连 PPT 验证

验证日期：2026-10-31（Asia/Shanghai）。已实现并本地验证，未发布，待用户验收。

## 使用流程

1. 当前比赛的计划书保留动态问卷和分章节生成，也支持在章节目录打开编辑器。
2. 核对正文、数字和来源后确认章节。AI 原文与用户修改分开保存；待补占位始终排除，推断需要额外人工核实。
3. 保存版本；可恢复最近 20 个本机快照，恢复产生递增的新版本，不覆盖历史。
4. 选择答辩时长、8—15 页和重点，点击“生成 PPT”。直接保存统一文档并生成大纲，无需上传 DOCX。
5. 编辑标题、要点、备注、顺序和页数。检查项目名、数字及所属结论、来源、评分覆盖、文字容量、空白和无依据结论。
6. 阻断问题修正后完成 Human Gate，导出原生可编辑 PPTX。来源缺失和显式待核验内容保留警告及标记。
7. 从页面回到原计划书章节修改；旧大纲会失效，须重新生成。不同项目/比赛的文档与草稿不会互相读取。

## 数据与来源边界

统一文档以 projectId、competitionId、trackId、revision 绑定，保存标题、章节、内容块、AI 原文、用户修改、证据/来源 ID、确认状态、版本和更新时间。服务端版本引用另含 documentId 与内容哈希。PPT 加载精确引用，禁止读取全局最新计划书；保存时拒绝低版本覆盖，生成与落盘前拒绝旧引用。

网页大纲从已确认原句中摘取。模型仅选择已确认内容块 ID，未知 ID 被排除，不允许直接输出新事实。非原句改写需先回计划书确认，或显式标为【待核验】。按已有关键词组织主题，缺失的创新/验证/资源不会靠其他技术段落冒充。客户端伪造的来源关联由服务端重建。

章节确认是用户对内容的确认，不等于官方来源核验。评分覆盖需同时有对应评分文字与来源关联，不能因共用一份官方文件就宣称覆盖全部评分点。旧来源快照须匹配当前核验缓存与原句；未匹配时降为待核验，并从官方评分上下文排除。

每页备注附项目/比赛、计划书版本、章节、内容块、evidenceId/sourceId 和核验提示。PPT 正文保留待补/待核验标签。外部 DOCX 兼容入口、文件限制、大纲编辑和下载仍可用，同样需要 Human Gate。
