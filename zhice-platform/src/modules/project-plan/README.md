# 项目计划书

入口 `/?view=plan`，三栏工作台展示动态问卷、预期结果报告/章节编辑器和原文上下文。前端使用 Zustand 保存 UI 与本机草稿，服务端上下文通过共享 API 客户端获取并经 Zod 解析。

## 绑定与上下文

每次请求必须带 `PlanWorkspace`：当前项目、比赛、赛道、选择版本、学生画像、用户确认时间、显式赛事要求报告 ID，以及 draft/formal 意图。`POST /api/project-plan/context` 只接受匹配全部绑定字段的报告，旧 GET 不再查找最新报告。问卷提示词和本地追问均结合当前比赛、赛道、学生目标/技能/团队/资源和已核验评分原句。

官方评分上下文只来自官方正文缓存中已人工逐字核验的条款，附原句、来源 ID 与链接。报告中的 AI `score-*` 区块、sample/demo 生成评分不作为官方条款。显式上传覆盖模式排除缓存官方条款。冲突状态取当前来源缓存，即使已有报告快照曾标为核验也会阻止正式生成。

## 状态门与生成

- 无比赛/赛道：不能进入正式对齐生成，提示先选择。
- 缺少已核验评分、赛道待核验或来源冲突：允许标明状态的草稿，阻止正式报告与初稿。
- 用户确认比赛与赛道、赛道已维护核验、存在已核验官方评分且没有来源冲突：允许正式计划书初稿，仍需人工审阅。

`POST /api/project-plan` 支持 survey、report、chapter 的 SSE 和 export 的 Markdown/DOCX。服务端校验会话与报告的绑定；评分对齐列表按允许的原文条款重新组装，剔除模型虚构的评分名称。报告附 `projectId/competitionId/reportId/requirementsReportId` 和来源；章节附绑定、草稿/正式状态及原文来源附录。正文使用【已生成】【建议补充】【AI推断，请核验】区分素材性质。

计划书以 `projectId + competitionId + trackId + revision` 持久化，异步回调检查范围。换赛保留旧材料历史，当前问卷/报告/章节从空状态开始。现有目录的演示赛道均待核验，不为启用正式按钮而伪造真实赛道或评分。

## 统一文档与直接生成 PPT

`shared/contracts/plan-document.ts` 定义文档标题、项目绑定、章节、内容块、AI 原文、用户修改、来源/证据 ID、版本、确认状态和更新时间。章节 store 的生成、编辑、确认和恢复动作同步维护统一文档。旧章节在当前范围内迁入文档，不分配给其他项目。编辑保留 AI 原文；未改动内容块沿用原始身份，修改的块标为用户内容。

文档面板提供章节目录、章节状态、保存版本和恢复（本机最近 20 个快照）。恢复内容后版本号继续递增，并同步更新章节编辑器。确认章节只确认普通已生成内容；【建议补充】和空白占位始终排除，AI 推断须额外勾选逐条核实才成为可引用素材。

`PUT /api/project-plan/document` 保存绑定文档，校验内容块确实出现在章节正文中。服务器在 `data/plan-documents/<binding-hash>/` 保存不可变版本与 current 指针，拒绝旧版本覆盖。返回 `{ data, reference }`，reference 包含 documentId、version、绑定和内容 SHA-256。`GET` 必须提供完整绑定，不查找全站最新文档。保存不代表核验官方来源。

“生成 PPT”先保存当前文档，再进入 PPT 大纲编辑器。可选择时长、8—15 页和重点，不需要上传或中转 DOCX。只使用当前范围的已确认章节及已确认内容块，缺口保留占位与警告。新增来源信息会产生新版本；计划书改变后旧大纲需要重新生成。详见 PPT 模块 README 与 `docs/plan-ppt-verification.md`。
