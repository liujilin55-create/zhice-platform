# 项目总览 / AI 工作台

入口 `/?view=overview`，主组件 `pages/dashboard/dashboard.tsx`。页面由 `AiBriefing`、`CoverageMatrix`、`QuickActions` 和共享的 `workspace/ActivityFeed` 组成。页面使用暗黑灰底、蓝紫渐变、键盘焦点状态和尊重 reduced-motion 的 hover 反馈；手机端保持两列微缩矩阵，操作卡片纵向排列。

## 数据与状态

- `GET /api/project-overview` 只按当前选择显式关联的 `reportId` 读取服务端报告，不再自动选择最新报告；`scope=empty` 用于空上下文。缺少报告时显示通用准备维度，不作为官方评分，也不将种子示例计入进度。接口数据在 hook 中管理，经 Zod 校验后进入页面。
- `coverage.ts` 根据报告的 `score-*` 区块、引用关联和证据状态推导矩阵。绿色要求 AI 报告、已确认的引用和已确认的真实来源同时成立；建议存在但依据未确认显示黄色；无建议显示灰色。废弃证据和示例来源不支撑绿色状态。维度跳转到 `/?view=requirements&report=...&criterion=score-n#coverage-score-n`，分析页读取同一份矩阵，定位并聚焦目标行，可继续打开原报告与证据。
- Zustand `workspace` 保存用户当前项目、一次性 File 交接及本机活动记录；`task-orchestration/task.store.ts` 保存用户执行任务，供两个页面共同使用。初始化模板任务标记为示例，不计入总览中的当前任务。报告和证据仍由服务端管理。
- “继续当前任务”优先定位当前项目的进行中任务，其次选择未完成任务或尚待核验的评分行；无报告时进入上传流程。“重新开始”进入学生画像/备赛项目页，用户可从该页新建独立项目，历史材料不被删除。

## 简报与快捷行动

`POST /api/project-overview/briefing` 返回 SSE：`meta` 指明 AI / 本地摘要，`delta` 追加文字，`replace` 明确替换失败的 AI 草稿，`complete` 表示结束，`error` 表示中断。8 秒连接心跳不模拟生成进度，55 秒取消超时；离开页面中止模型调用。简报使用后台 `projectOverview` 独立配置及其提示词，只读取与当前项目关联的报告。无模型时立即提供标注为本地摘要的确定性内容。会话内同上下文缓存 5 分钟；用户可手动更新。

项目首页的“继续材料准备”只提供四步入口：画像与选赛、定题与找依据、计划书与 Word、PPT 与材料自查。比赛文件上传与规则分析从第一步进入，论文、案例和证据从第二步进入，PPT 与提交前检查从第四步进入；对应页面仍保留原有独立路由，便于历史链接和核验链接继续工作。

任务流显示当前项目真实操作的最近 5 条记录，包括进行中、成功、警告和失败，时间与耗时由操作起止时间计算。分析步骤、论文检索、PPT、项目简报和任务变更均写入带 `projectId` 的记录。“查看全部任务”进入当前项目任务编排及本机日志。工作空间合计保留最近 1000 条记录，属于当前浏览器，不冒充跨设备同步。

## 验证

`node --test tests/dashboard.test.mjs` 覆盖矩阵来源与确认状态、SSE 中文碎片、无配置兜底、真实 AI SDK 流、失败替换、取消及本机状态边界。测试替换模型与证据库，既不使用真实密钥，也不更改用户报告。
